## Product summary

Puente listens to speech in any supported language, detects the source language, and translates each complete utterance into a user-chosen **base language**. All inference runs **on-device** after the model is downloaded once.

Target platforms: **Android and iOS** (primary). Web is optional — if unsupported by a native module, show a clear fallback message on web instead of crashing.

## Task 4 — Supported languages module

Create `src/constants/languages.ts`:

- Export the full list of NLLB-200 FLORES codes supported by `Xenova/nllb-200-distilled-600M` (e.g. `eng_Latn`, `spa_Latn`, `tha_Thai`, …).
- Each entry: `{ code: string; label: string }` where `label` is a human-readable name ("English", "Español", "ไทย", …).
- Export helpers:
  - `getLanguageLabel(code: string): string`
  - `resolveDeviceBaseLanguage(): string` — map `expo-localization` locale to nearest supported FLORES code; **fallback `eng_Latn`** if unsupported.
  - `mapSpeechLocaleToFlores(detectedLocale: string): string | null` — map BCP-47 from speech recognition (e.g. `es-ES`, `en-us`) to FLORES code; return `null` if unmappable.

**Base language default (every cold start):** on each app launch, automatically set base language from the phone locale via `resolveDeviceBaseLanguage()` — use device language if supported by NLLB, otherwise **`eng_Latn` (English)**. User can override in the language picker for the **current session only** (React state — no Redux, no AsyncStorage).

## Task 7 — Speech recognition pipeline

Create `src/hooks/use-speech-translator.ts` (or split into hook + service):

### Permissions
- Request microphone permission before starting. If denied, show inline error on main screen — do not crash.

### Start (when user taps Start)
Use `expo-speech-recognition`:

```tsx
ExpoSpeechRecognitionModule.start({
  lang: 'auto', // or omit — detection handles source language
  interimResults: true,
  continuous: true,
  androidRecognitionServicePackage: 'com.google.android.as',
  requiresOnDeviceRecognition: true,
  androidIntentOptions: {
    EXTRA_ENABLE_LANGUAGE_DETECTION: true,
  },
});
```

Listen to events via `useSpeechRecognitionEvent`:

| Event | Action |
|-------|--------|
| `result` | Accumulate transcript. When `event.isFinal === true` and text is non-empty → enqueue for translation |
| `languagedetection` | Store `event.detectedLanguage` (BCP-47) for the current/final utterance |
| `error` | Log, surface user-friendly message, auto-stop if unrecoverable |
| `end` | If still in "listening" mode, restart recognition (continuous session) |

### Stop (when user taps Stop)
- Call `ExpoSpeechRecognitionModule.stop()` / `abort()`.
- Cancel any in-flight translation for partial utterances.
- Do **not** clear existing messages.

### Utterance → translation flow
1. Final speech result arrives with text + detected locale.
2. Map locale → FLORES `src_lang` via `mapSpeechLocaleToFlores`. If null, skip or use best-effort fallback and still attempt translation.
3. If `src_lang === baseLanguage`, skip translation (optional: show original text anyway — pick one behavior and document in code).
4. Call translator: `translator(text, { src_lang, tgt_lang: baseLanguage })`.
5. Append `{ id, sourceLanguage, sourceLabel, translatedText, timestamp }` to messages state.
6. Serialize translations — process one at a time or queue; avoid duplicate processing of the same utterance.

### Platform notes (implement gracefully)
- **Language detection** via `EXTRA_ENABLE_LANGUAGE_DETECTION` is **Android 14+ only** with on-device service `com.google.android.as`.
- **iOS:** speech recognition works; auto language detection may be limited. Use recognizer locale or default to device locale when detection unavailable — never block the feature entirely on iOS.
- Handle Android < 14: fall back to device locale as `src_lang` estimate; show no error unless mic unavailable.
